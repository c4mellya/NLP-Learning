# 实验开发过程

## 探索

选题聚焦 Prompt Caching 与稳定前缀。学习问题是：为什么只改最后的问题通常还能复用前面的计算，而在开头改一个字符会影响后续内容？

资料阅读围绕三件事展开：因果注意力与 KV 前缀复用、OpenAI 与 Anthropic 的缓存入口、响应中用量字段的含义。把缓存机制和具体服务商规则分开，避免将模型相关参数误当成统一原理。

## 规格化

AGENTS.md 按 Task、Constraints、Data、Output 组织。核心任务是解释稳定前缀，不扩展为知识百科；交互需要让学生编辑内容、看到分叉、理解读写成本。原生 HTML、CSS、JavaScript 对应独立单页交付。

## 第一轮建构

第一版以概念说明、预设动画和 API 代码对比组织内容。主要问题是交互行为规定得不够具体，动画能表达变化，但没有清晰的编辑与发送边界。问题记录转入 prompt-log.md，作为第二版规格的输入。

## 第二轮迭代

将请求拆成四段可编辑内容，补充时间戳、工具顺序和用户问题场景。明确编辑更新预览，发送记录缓存，过期清空状态。缓存网格与用量字段共同表达命中、写入和重新计算，成本图解释多轮 Agent 中稳定前缀的意义。

教学数据使用简化 token 与示意倍率，不依赖真实模型请求。这样学生可以反复改变输入并观察机制，避免把一次服务端命中结果误当成必然规律。

## 反刍与整理

结合 Hermes prompt_builder.py 理解项目上下文怎样进入 Prompt，并把稳定内容与变化内容的排列同网页实验联系起来。整理两版 Prompt、问题归因和 Runtime / Prompt / Eval 的分工，形成实验总结。

## 交付组织

网页入口为 index.html，资源在 assets/，字体许可在 licenses/，规格与实验过程分别保存在 AGENTS.md 和 logs/。页面正文不依赖服务器端逻辑，可以作为个人独立静态站点发布。

sec.1 / 5 · 机制

缓存的是什么？是前缀的 KV

Transformer 解码时，第 t 个 token 的注意力要读取前 t-1 个 token 的 K 和 V。这些 K/V 只取决于前缀本身，跟你这次问什么毫无关系。既然同一个前缀算多少次结果都一样，服务商就把它暂时存起来——再来一个前缀完全相同的请求，直接调旧账，不用重算。

如果你在本机推理里用过 KV cache：prompt caching 就是把它从「一次请求之内」搬到「多次请求之间」。省的是 prefill 的计算，落到你账上就是钱和延迟。

[a]只认前缀

匹配从第一个 token 开始逐字节进行。尾部追加不影响命中；但前缀里动一个字节，从那一秒起后面全完。

[b]认死理

不相似、不近似，字节不同就是不同。「的」和「得」是两个世界；多一个空格也是一次失效。

[c]有保质期

缓存有保质期：Anthropic 5 分钟档命中即刷新（另有 1 小时档）；OpenAI GPT-5.6+ 的 ttl 默认 30m；DeepSeek 可达数小时至数天。过期等于冷启动。

HIT字节级相同
MISS第 5 个 token 起不同

Anthropic：需显式打下 cache_control 断点（最多 4 个），各模型另有最小可缓存长度[1]；OpenAI GPT-5.6+：内容块级断点，可用 prompt_cache_breakpoint 显式打点（每请求最多 4 个）[2]。

sec.3 / 5 · 三家对比

同一件事，三种做法

OpenAI、Anthropic、DeepSeek 都在做同一件事——前缀匹配 + 短 TTL + 命中记账，但开启方式与溢价结构分成两条路线：OpenAI GPT-5.6+ 与 Anthropic 走「显式断点 + 写溢价」，DeepSeek 则是默认开启、不单收写溢价。

sec.4 / 5 · 成本模拟

算账：缓存到底省多少

模型：每轮请求 = 稳定前缀 + 逐轮追加的新内容。无缓存时每轮全价重算；有缓存时命中部分按读价、新内容按原价；失效的那轮把整个前缀按写价重写。前缀低于该提供商的最小可缓存长度时，缓存根本不建立——按无缓存计费，并在这里明确警告。单位是「等效全价输入 token」，自己乘单价即得美元。

sec.5 / 5 · 陷阱与决策

五个暗坑，一张决策单

大多数缓存失效不是「改了一个字」，而是无意识地把每轮变化的内容塞进了前缀，或者压根没到门槛。五个最常见的暗坑：

暗坑 1 · 时间戳前插

把当前时间拼在 system 最前面，等于每轮换一个前缀。

system = "现在 " + now + "\n" + BASE // 每轮都不同 → 永远冷启动
BASE 保持字节稳定；now 放进最后一条 user 消息

暗坑 2 · tools 增删或重排

工具定义位于前缀。中途加一个工具、调一次顺序，前面全部作废。

tools 数组每次重新排序 / 条件拼接 // 前缀字节变化
工具集固定序列化；必须变时，接受一次写价重写

暗坑 3 · JSON 键序不稳

同样内容、不同字节序，就是不同前缀。

{"b":1,"a":2} 与 {"a":2,"b":1} // 逐字节比较 → 不相等
固定键序（如 sort_keys）后再进 prompt

暗坑 4 · 动态内容放在断点前

RAG 检索结果每次不同，却拼进 system 或断点之前。

system = 检索结果 + 规则 // 检索一变，全失效
规则与静态文档走缓存；检索结果放到尾部再追加

暗坑 5 · 门槛之下的静默失败

前缀没到最小可缓存长度，或断点打在了太靠前的位置：接口不报错，只是永远不命中。

prefix = 400 token // 低于该模型的最小可缓存长度 → 压根不进缓存，也无从「命中」
先确认门槛，再决定要不要为写溢价买单

判断顺序 · 先门槛，再前缀，最后 TTL

把这三个问题按顺序问一遍，比事后看账单便宜得多。

1) 前缀够长吗？（Anthropic 512–4,096 / DeepSeek 无明示） 2) 前缀字节真的稳定吗？（ tools / 键序 / 时间戳） 3) 会在一两个 TTL 内复用吗？（间隔短于 TTL）

[+]缓存省钱，当……

  • 前缀达到门槛（Anthropic 依模型 512–4,096 token）且重复使用 ≥2 次
  • 固定文档库 / RAG 语料放在最前，逐题只改尾部
  • Agent 的 system + tools 固定，多轮对话用追加式
  • 请求间隔短于 TTL，或持续有流量保温
  • 写溢价的一次性成本能被多次读摊薄（Anthropic 5 分钟档 1 次读即回本）

[-]反而更贵，当……

  • 只问一次：Anthropic 写价 1.25×（GPT-5.6+ 同样收 1.25×），一次读赚不回来
  • 前缀短于门槛：不是「少省一点」，是根本不进缓存
  • 每轮都污染前缀：失效一次，整个前缀按写价重算
  • 超过 TTL 再来：冷启动 + 重新写一遍

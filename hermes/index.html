课程 01 / Agent · CLI

Hermes Agent 六步上手

Hermes 是 Nous Research 开源的自主 agent（MIT、自托管、Python）。这份材料不做「它很厉害」的介绍，只把官方文档里最必要的内容压成一条六步路线：命令能在 Shell 里找到、模型和 Provider 配好、能跑通第一次对话并恢复会话、能看懂状态与 Context、分得清普通配置与 Secret、并且能让它用工具真的产出一个文件。

每一步都给四样东西：官方文档入口、要做什么、可直接照抄的命令、以及验收方式。没通过验收就不该往下走。

官方学习路径

STEP 01 / 安装

安装 Hermes Agent

从环境检查到启动诊断，建立一条可重复验证的安装路径。

官方文档

学习目标

完成“检查环境 → 执行安装 → 重新载入 Shell → 启动验证 → 诊断问题”的完整流程，并知道安装方式、命令入口与用户数据目录各自在哪里。

开始前需要知道

图形安装

  • macOS 与 Windows 可选择 Desktop 安装器
  • 适合希望由图形界面引导完成安装的学习者

命令行安装

  • Linux、macOS、WSL2、Termux 使用 shell 脚本
  • Windows 原生环境使用 PowerShell 脚本

非 Windows 平台主要需要 Git；Linux 还需准备 curl 与 xz-utils。其余主要依赖通常由安装器处理。执行前仍应以官方安装页的当前说明为准。

分步操作

下面两种脚本按平台二选一，不要混用。

bash / PowerShell
# Linux / macOS / WSL2 / Termux
$ curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

# Windows 原生 PowerShell（二选一）
PS> irm https://hermes-agent.nousresearch.com/install.ps1 | iex

# 重新打开终端，或按当前 Shell 重新载入配置后验证
$ source ~/.bashrc
$ command -v hermes
$ echo $PATH
$ hermes
$ hermes doctor

安装器大致会准备运行环境、获取代码、创建隔离环境、安装依赖并使 hermes 命令可用。普通用户数据通常存放在 ~/.hermes/，与安装代码的职责不同。

结果观察与排错

现象先检查处理方向
command not foundShell 是否重新载入、command -v hermes 与 $PATH重开终端或修正 PATH，再执行诊断
缺少 API KeyProvider 是否完成认证运行 hermes model，只在 Secret 存储中录入凭据
配置缺失hermes doctor 与配置检查提示按提示补齐配置，再运行 hermes config check

核心理解

脚本执行结束不等于安装完成。只有命令能被 Shell 找到、交互界面能启动且诊断命令能指出环境问题，才形成了可验证的安装闭环。

验收方式

  • hermes 命令可执行并能进入交互界面
  • 能说出自己的安装方式以及 ~/.hermes/ 的用途
  • 知道用 command -v hermes 与 echo $PATH 检查命令入口
  • hermes doctor 可运行并用于诊断

本步总结

安装的结果不是“脚本跑过”，而是获得可启动、可定位、可诊断的 Hermes CLI。

STEP 02 / 快速开始

完成第一次 Hermes 对话

配置模型、进行两轮可验证对话，并恢复最近会话。

官方文档

学习目标

沿着“初始化 → 配置 Provider/Model → 第一次对话 → 恢复会话”的最短路径跑通模型调用，并能判断一次对话是否真正成功。

核心流程

01初始化
→
02配置 Provider / Model
→
03第一次对话
→
04恢复会话
模型选择提示

学习工具调用时，建议选择上下文上限至少 64K token 的模型。Secret 不应写入本页面、对话示例或公开仓库。

分步操作

bash
# 1. 配置 Provider、认证方式与模型
$ hermes model
# 可选：通过 Portal 引导初始化
$ hermes setup --portal

# 2. 任选一种入口开始对话
$ hermes
$ hermes --tui
$ hermes chat -q "请用三点解释工具调用，并给出一个可验证示例"

# 3. 查看与恢复会话
$ hermes sessions list
$ hermes --continue
$ hermes -c

第一次提问应具体、简单、可验证；收到回答后继续追问一次，例如要求澄清其中一点。恢复结果取决于所用 profile 以及会话是否已保存，因此恢复前先确认当前 profile 和会话列表。

成功观察与基础排查

  • 启动信息展示预期的 Provider 与 Model
  • 没有认证或网络错误，并能完成至少两轮连续追问
  • 任务需要时，Hermes 能显示并调用可用工具
hermes doctor→hermes model→重启对话→检查会话列表

核心理解

Quickstart 先验证 Hermes → Provider/Model → 回复 → 会话保存 的最短闭环。只有连续对话和恢复都成功，才说明基础链路不只是偶然返回了一条消息。

验收方式

  • Provider 与 Model 已完成配置
  • 围绕同一问题完成至少两轮连续对话
  • 能从启动信息判断模型链路没有认证或网络错误
  • 使用 hermes --continue 或 hermes -c 成功恢复最近会话

本步总结

第一次成功使用包含配置、对话、观察与恢复四个环节；它是后续 CLI、配置和工具学习的基线。

STEP 03 / 模型配置

理解模型服务配置

理解连接链路中的五个概念，并安全配置教师提供的 API。

官方文档

学习目标

能解释 Provider、Model、Base URL、API Key/OAuth、API mode 的职责，区分配置向导与会话内切换，并完成一次明确指定模型的验证。

完整连接链路

Hermes→Provider→Base URL→Model→API Key / OAuth↔API mode
Provider
提供模型服务或兼容接口的平台；它决定请求发往哪类服务。
Model
实际执行推理的模型标识。标识必须与 Provider 端开放的模型一致。
Base URL
API 请求的服务根地址。自定义兼容服务尤其需要核对路径。
API Key / OAuth
证明访问权限的认证方式。Key 属于 Secret；OAuth 凭据由认证存储管理。
API mode
请求与响应所遵循的接口协议模式，必须和目标服务兼容。

两个 model 命令的区别

入口用途边界
hermes model新增 Provider、完成认证、配置模型终端中的配置入口
/model查看或切换已配置项只在当前交互会话内使用，不负责新增认证

推荐操作流程

bash / hermes 交互
$ hermes model
$ hermes config
$ hermes chat --provider <provider-name> --model <model-id> -q "请回复：配置验证成功"
$ hermes
> /model

普通配置放入 config.yaml，API Key 等 Secret 放入 .env，OAuth 由认证存储管理。

config.yaml
model:
  provider: <provider-name>
  default: <model-id>
  base_url: https://provider.example/v1
  api_mode: <api-mode>

结果观察与常见错误

错误检查方向
认证失败确认 Provider、Key/OAuth 状态与 Secret 位置，不打印凭据
模型 ID 错核对教师提供的 <model-id> 与大小写
Base URL 错核对协议、主机与接口路径，避免重复路径
API mode 不匹配确认服务要求的请求协议并修改普通配置
上下文不足改用满足任务上下文要求的已配置模型，或缩小输入

核心理解

Hermes 负责 Agent 行为、工具与任务流程；Provider 负责模型推理与鉴权。配置就是把协议、地址、模型和认证正确地连接起来。

验收方式

  • 能解释 Provider、Model、Base URL、API Key/OAuth、API mode 五个概念
  • 能说明 hermes model 与 /model 的区别
  • 按安全存储规则成功配置教师提供的 API
  • 明确指定 Provider 与 Model 后能收到验证回复

本步总结

模型配置是一条端到端连接链；任一环节不匹配，都应按概念边界逐项定位。

STEP 04 / CLI

掌握 Hermes 常用命令

从启动、交互到恢复，学会读懂状态和 Context。

官方文档

学习目标

能选择合适的启动方式，使用五个核心斜杠命令，并完成多行输入、中断操作与会话恢复。

启动方式

bash
$ hermes
$ hermes --tui
$ hermes chat -q "请概括当前任务"
$ hermes --continue
$ hermes --resume <session-id>

前两项进入交互界面，chat -q 适合单次问题；后两项分别恢复最近会话与指定会话。

命令速查

选择命令查看用途与通用占位输出；页面内容不代表当前机器的实际状态。

作用

示例输出
学习提示

如何阅读状态与 Context

Model / Provider
确认请求将使用哪个已配置模型以及模型服务来源。
会话状态
判断会话是否可继续工作，出现异常时结合诊断命令排查。
工具 / 文件摘要
了解当前可用能力以及会话已涉及的文件范围。
Token 使用
同时看已用 token、上下文上限和占用比例，而不是只看单一数值。
压缩
接近上限时关注压缩状态；压缩用于保留关键信息并释放上下文空间。

输入与会话操作

操作用途
Enter发送当前输入
Alt+Enter / Ctrl+J插入换行，编写多行提示
Ctrl+C中断当前生成或操作；使用后检查会话状态
Tab在支持的输入位置补全命令或候选项
/title为当前会话设置便于识别的标题

顺序练习与结果观察

hermes 交互
> /help
> /model
> /tools
> /status
> /context
# 退出后在 Shell 中恢复
$ hermes --continue
占位输出

        
按顺序执行后，口头说明当前模型与 Provider、可用工具、Context 占用与压缩状态；再用多行输入发送一条消息，并练习中断一次可安全重试的生成。

        
核心理解
斜杠命令是对“当前会话”的观察入口，Shell 参数负责“如何启动或恢复”。把两类入口分清，排错时才不会把会话切换误当成全局配置。

        
验收方式
  • 能用 /help、/model、/tools 查看帮助、模型和工具
  • 能用 /status 与 /context 解释状态、用量和压缩
  • 能完成多行输入并使用 Ctrl+C 中断
  • 能退出并恢复最近一次或指定会话

        

        
本步总结
CLI 学习的核心是会启动、会观察、会控制、会恢复，而不是记住所有高级命令。

        
      


      

        
STEP 05 / 配置文件
区分普通配置与 Secret
理解目录职责、配置优先级，并通过 CLI 安全管理配置。

          
官方文档

        

        
学习目标
能找到四个核心文件，解释配置覆盖顺序，使用 CLI 查看、修改、检查配置，同时不展示或提交任何 Secret。

        
~/.hermes/ 目录职责
目录树
~/.hermes/
├── config.yaml   # 普通运行配置
├── .env          # API Key 等 Secret
├── auth.json     # OAuth 认证存储
├── SOUL.md       # Agent 身份与行为说明
├── memories/     # 长期记忆资料
├── skills/       # 可用技能
├── sessions/     # 已保存会话
└── logs/         # 诊断日志

        
配置文件查看器
以下均为教学占位符，不是当前机器配置，也不包含真实凭据。
~/.hermes/
config.yaml

        
使用 CLI 管理配置
bash
# 查看与编辑
$ hermes config
$ hermes config edit

# 设置普通值与 Secret（示例仅用占位符）
$ hermes config set model.default <model-id>
$ hermes config set PROVIDER_API_KEY your_api_key_here

# 检查与迁移
$ hermes config check
$ hermes config migrate
普通配置还可通过环境变量引用，例如 api_key: ${PROVIDER_API_KEY}；示例和值都只使用占位符。

        
配置优先级
CLI 参数→config.yaml→.env→内置默认值
左侧优先级更高。CLI 参数适合一次性覆盖，不必改变持久设置；config.yaml 与 .env 用于需要跨会话保留的配置，二者分别承载普通值与 Secret。

        
普通配置 vs Secret
普通配置 · config.yaml
  • Provider、Model、Base URL
  • 终端后端、压缩与工具选项
  • 可安全分享的功能设置
Secret · .env / 认证存储
  • API Key 与 Token
  • Password
  • OAuth 凭据
安全说明
不要把真实凭据写进前端页面、config.yaml、聊天记录或公开仓库；也不要通过截图、日志或命令输出展示 Secret。

        
练习与结果观察
  • 运行 hermes config 查看普通配置
  • 确认 config.yaml 中没有 API Key、Token 或 Password
  • 找到 Secret 存放位置，但不要打开、复制或展示其内容
  • 用 CLI 修改一个非敏感值，再运行 hermes config check

        
核心理解
配置管理同时解决“行为如何持久化”和“凭据如何隔离”。优先级帮助解释最终生效值，文件边界帮助避免 Secret 泄露。

        
验收方式
  • 能找到并说明 config.yaml、.env、auth.json、SOUL.md 四个核心文件
  • 能解释 CLI 参数到内置默认值的优先级
  • 能通过 CLI 查看、编辑、设置并检查配置
  • 操作与分享过程中不泄露 Secret

        

        
本步总结
普通配置决定 Hermes 如何运行，Secret 只提供访问权限；正确的优先级与存储边界同样重要。

        
      


      

        
STEP 06 / 工具调用
让 Hermes 完成真实任务
理解 Tool Calling 循环，并交付一个可人工复核的文件结果。

          
官方文档

          
官方文档

        

        
学习目标
理解从任务判断到文件交付的 Tool Calling 循环，识别实际使用的工具，并比较 local 与 docker 执行环境的基本差别。

        
Tool Calling 核心循环
理解任务→选择工具→执行调用→读取结果→继续行动→交付文件
模型负责决定下一步，工具负责对环境执行动作；每次结果都会成为后续判断的依据，所以最后还要重新读取产物，而不是只相信“已完成”的文字回复。

        
常见工具类型
类型教学职责
terminal / process执行命令与管理进程
read_file / patch读取文件与进行受控修改
web_search / web_extract检索网页与提取所需内容
todo / delegate_task规划任务与委派独立工作
memory / session_search查找记忆或历史会话信息
名称随配置与版本能力而异，实际可用工具始终以 hermes tools 或会话内 /tools 输出为准。

        
工具集与执行环境
bash
$ hermes tools
$ hermes chat --toolsets "terminal,file"
$ hermes config
# 可选：按配置文档将 terminal.backend 设为 docker
local
  • 直接在本机允许的范围内执行
  • 访问方便，但需更谨慎地限定路径与命令
docker
  • 在隔离容器环境中执行
  • 隔离更清晰，但需准备 Docker 与必要的挂载/权限

        
完整练习
练习输入固定为两条记录；要求 Hermes 读取、计算、写入并复核。
bash / hermes 交互
$ printf "category,amount\nSoftware,299\nMedia,88\n" > sales.csv
$ hermes
> 读取 sales.csv，统计记录数、总金额和平均金额，将结果写入 summary.md；重新读取文件验证，并说明实际使用的工具。
$ cat summary.md

        
任务流程与结果观察
01读取输入读取 sales.csv
↓
02分析计算记录数、总金额、平均金额、分类
↓
03写入结果使用文件修改工具或 terminal 创建 summary.md
↓

人工复核期望

安全原则
  • 调用前确认工具权限与实际可用范围
  • 限定输入文件、输出文件和工作目录
  • 对删除、覆盖与联网操作保持谨慎，必要时先请求确认
  • 不信任输入或风险较高时使用隔离环境
  • 交付前重新检查产物内容和路径

        
核心理解
Tool Calling 的价值在于产生可验证的环境变化。清楚记录“为何选工具、工具返回什么、如何据此继续”，比只得到一段回答更重要。

        
验收方式
  • Hermes 成功读取 sales.csv，并能说出实际调用的工具
  • 记录数、总金额、平均金额与分类全部正确
  • summary.md 真实存在且经过重新读取验证
  • 能解释完整 Tool Calling 循环以及 local / docker 的差别

        

        
本步总结
工具让 Hermes 从“回答问题”走向“执行并交付”；真实文件、正确数值与复核过程共同构成验收证据。
